# AGENTS.md

## What this repo is

Single-host NixOS flake for a QEMU VM (host `nixos`), tracked in git. No CI, tests, or linter — Nix evaluation is the check. Uses the dendritic pattern: flake-parts + `import-tree`, where every file under `modules/` is itself a flake-parts module.

- `flake.nix` — minimal entrypoint. `flake-parts.lib.mkFlake` evaluates `import-tree ./modules`; outputs are `flake.nixosConfigurations.nixos` and the `flake.nixosModules.*` set. nixpkgs pinned to `nixos-unstable` in `flake.lock`.
- `modules/` — auto-imported recursively by `import-tree`. Each file declares exactly one `flake.nixosModules.<name>` feature module (NixOS module inside the flake-parts module); **do not `import` one module from another**, declare it instead. Files/dirs starting with `_` are ignored by `import-tree`.
  - `modules/hosts/nixos.nix` — defines `flake.nixosConfigurations.nixos` by selecting which `self.nixosModules.*` make up the host. Add a new module to this list to activate it.
  - `modules/hardware/qemu-guest.nix` — wraps the generated `hardware-configuration.nix` as `nixosModules.hardware`.
  - `modules/system/` — boot, networking, OpenSSH, packages (`vim`/`wget`/`opencode`/`herdr`), `state-version`.
  - `modules/users/alfrest.nix` — user `alfrest` (`wheel`).
- `hardware-configuration.nix` — generated by `nixos-generate-config`; **never edit** (btrfs subvolumes, `qemu-guest.nix`). Referenced via `modules/hardware/`, so keep it at the repo root.
- `/etc/nixos` is a root-owned copy of the old pre-dendritic layout. Edits here are not live until rebuilt from this directory.

## Verification is mandatory

Flakes are disabled system-wide (`/etc/nix/nix.conf`), so flake commands need:

```sh
export NIX_CONFIG='experimental-features = nix-command flakes'
```

After any change, run these and never report success on a non-zero exit:

1. Syntax: `for f in flake.nix modules/*/*.nix; do nix-instantiate --parse "$f"; done` (works without the flag)
2. Flake evaluation: `nix flake check` (evaluates `nixosConfigurations.nixos`, no build)
3. Build without activating: `nixos-rebuild dry-build --flake .#nixos`
4. Package exists in the locked nixpkgs: `nix eval --raw .#nixosConfigurations.nixos.pkgs.<name>.name`

Formatting: `nixfmt`/`alejandra` are not installed, and the stock files are not nixfmt-clean. Only if you intentionally format, use `nix shell nixpkgs#nixfmt-rfc-style -c nixfmt -w configuration.nix`; do not reformat `hardware-configuration.nix`.

## Commands

- Apply now: `sudo nixos-rebuild switch --flake .#nixos`
- Stage for next boot: `sudo nixos-rebuild boot --flake .#nixos`
- Update nixpkgs: `nix flake update`
- Inspect inputs: `nix flake metadata`

Without `--flake`, `nixos-rebuild` targets `/etc/nixos`, not this repo. `sudo` needs a password here (`sudo -n` fails), so ask the user to run privileged rebuilds.

## Constraints

- Never change `system.stateVersion` (`"26.05"`), even after upgrades.
- Always select the `.#nixos` flake attribute.
- Flakes read git-tracked files only: `git add` new files before `nix flake check` or `nixos-rebuild`, or they will be invisible.
